# 继续当前 Windows 客户端的 P0 验证

当前应用没有 CDP，不能直接通过现有会话注入 Renderer。Loader 上游明确要求先关闭运行中的 Codex，再通过 Loader 启动；此动作会中断当前聊天执行，需选择合适时机。不得把现有通用用量工具或独立 App Server 当作 Renderer 数据源通过的证据。

## 重启前准备

1. 保持项目工作树干净，保留当前开发分支，执行 `bun run check`、`bun test`、`bun run build`。探针包在 `dist/probe`，不依赖全局配置，不修改安装包。
2. 使用已经审阅的固定 Loader 源码 b6ec28c69af12e9667f57d19823fb46d225756e4（package 0.6.0），原生 Windows Node 22+。不要改用未经审阅的 latest 安装器。临时调研源码可能被系统清理，缺失时按该 commit 重新获取并审阅。
3. 选择独立测试数据目录，不复用生产 Loader 配置；安装探针前确认只启用该探针，默认示例 UI 保持禁用。上游 Node 开发宿主不具有 Native Host 的全部安装和自动更新能力，本轮只验证 P0。

## Loader 命令

下面在原生终端运行；将变量设置成当前机器实际路径，文档不保存用户目录或会话信息。准备脚本只初始化空的独立目录并禁用上游默认示例（上游 CLI 默认会启用它），不启动应用。`run --live` 需要所有 Codex 窗口已经正常关闭。

```powershell
# $NodeExe：原生 Node 22+；$LoaderRoot：固定 Loader 源码目录
# $ProbePackage：构建后的 dist/probe；$ProbeData：独立的临时测试目录
& $NodeExe "$ProjectRoot/tools/probes/prepare-loader.mjs" $LoaderRoot $ProbePackage $ProbeData
& $NodeExe "$LoaderRoot/src/cli.mjs" scripts --data-dir $ProbeData
# 正常关闭 Codex 后执行；不要强杀仍在运行的聊天或任务。
& $NodeExe "$LoaderRoot/src/cli.mjs" run --live --data-dir $ProbeData
```

重启后回到本聊天继续。Loader 生命周期日志应包含 anchors、capabilities、markers 和 renderer-wham 或有限错误码。若 anchors 为 missing/ambiguity/space/structure，不强行插入；根据实际语义 DOM 更新独立适配规则，再重新验证。

## 实机采集顺序

1. 确认客户端 build、OS/架构、主题、缩放、语言，内存确认账号及工作区归属。
2. Renderer 额度与独立 App Server、原生 Usage 尽量在 5 秒内采样。reset 不同或跨重置时重采；不能确认同账号则标无法比较。
3. 检查 Composer 和 rail 的候选数、适配器 ID、空间检查和实际截图。P0 标记不等于正式圆环 UI，几何 ready 不等于视觉验收通过。
4. 验证输入、发送、Tab/focus、原生菜单、任务切换、Composer/rail 重建、设置页、两主题、常见/最小窗口尺寸和缩放；记录失败与重试。
5. 禁用、热重载、再启用后确认没有旧标记和迟到日志；以无 `[data-cui-probe]` 残留作为清理的一项检查，而非全部验收。
6. P0 仅 Weekly 的真实账号暂时不可用时，明确该实机场景待测；数据层合成测试不能替代实机三处 UI 验收。

Windows 平台完整通过之后，再实施 P1 Store/Scheduler、P2 圆环与共享 Popover。macOS 与 ARM64 仍需分别验证。正式发布前还须按原方案完成 30 分钟使用稳定性观察、完整回归、安装/禁用/卸载/升级和平台兼容报告。
