# UI 当前设计决策

本文件记录用户在本聊天中最新明确确认的展示方式；与原方案、历史 P0 截图或旧说明冲突时，以本文件为准。

## 当前方案（2026-11-09）

1. Composer 指示器位于输入框**外侧下方**。用户已通过选项明确排除底部控制栏内，并提供红色轮廓示意图。
2. 该区域为与输入框等宽的圆角矩形信息栏，栏内**只显示文字剩余量并靠右对齐**，例如 `5H 剩余 39% | WEEK 剩余 99%`。数字必须来自实际返回的对应窗口，示例不是固定值。
3. Composer 不创建 SVG、圆环、圆环图标或圆环占位；圆环仅用于侧栏。输入框下方为静态文字，不创建按钮、Tab焦点、悬停提示或点击/悬停详情入口。详情仅由侧栏圆环打开，侧栏保留键盘及可访问名称。
4. 原生输入区尺寸、模型/权限/发送控件保持其原有行为。两个圆角矩形**部分重叠，不留间隙**：信息栏矩形高约44px，上部约12px为装饰重叠区域，实际增加约32px外围空间。仍使用外围sibling，不重设编辑器高度或改变输入内容。重叠部分透明、不接收鼠标事件；可交互文字位于原生输入框下方。
5. 侧栏沿用已验证的原生 rail 内宽约束，当前 52px rail 中圆环宽36px；不能为固定40px圆环撑宽原生 rail。
6. 只有 Weekly 时，文字栏、侧栏和详情均完全移除 5H 部分；文字单项仍靠右，不留下占位，不因此报告连接异常。此处右对齐取代原方案的Composer单项居中；侧栏圆环仍按容器居中。
7. 详情底部的刷新说明仅为“每 30 秒刷新”，移除“采样”和异常退避等实现说明；实际失败退避及Retry-After行为继续保留在调度层。更新时间显示最近一次成功取数的本地绝对时间，不将带毫秒精度的有效时间显示为未知。
8. 真实剩余额度为0时，下方文字和详情直接显示“已经用尽”；侧栏保留0%数字，悬停提示和可访问名称同步为已经用尽，不再提示即将用尽。很小的正数仍按真实余量处理，不因舍入而误报已经用尽。
9. Work 新建窗口与 Codex 新聊天页不显示输入框下方额度文字栏；仅在已有聊天的输入区显示。适配器使用原生 thread footer 与 composer 标记作为挂载前置条件，缺少标记时不创建占位。侧栏规则保持不变。

## 本次验证（2026-11-09）

新增新建页拒绝挂载及聊天标记恢复的合成 DOM 回归；类型检查、167 项单元测试及构建通过。随后已通过当前 Windows Loader 会话热加载并完成实机检查：Work 新建页及 Codex 新聊天页均无 Composer slot、无文字栏残留，侧栏保留；两页可见输入区均为 `data-composer-placement="home"`，无 thread footer/find 标记。返回已有聊天后 Composer 与 rail 均恢复为 ready，各有一个 slot，文字额度正常显示。本次覆盖当前主题、尺寸下的页面切换，不代表完整平台矩阵通过。

## 历史方案及状态

最初的输入框下方双圆环已被用户明确替换。随后曾建议在红框所示控制栏内缩小显示，尝试了 Loader 官方 Composer Accessory；当前窗口未取得可用挂载点，临时预览已清理。用户最终改为本文件中的外侧文字栏，因此不再开发控制栏内的回退实现，也不为该方案申请 composer 权限。

旧截图仅作为历史测试证据，不得作为当前目标。当前仍处开发版：Loader 运行时和自动刷新已接线，并在原生 Windows 验证短暂运行、结构变化触发检查、热重载及停用清理；完整页面重建、身份切换、真实键盘及跨平台验收尚未完成。
