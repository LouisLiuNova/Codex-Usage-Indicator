# 开发版使用指南

本指南适用于 `0.1.0-dev.1`，面向愿意自行构建并验证的用户。当前没有正式发布包或一键安装器。Windows x64 与 macOS Apple Silicon 已有局部实机证据，完整范围见[当前状态](当前状态.md)。

## 环境准备

| 项目 | 要求 |
| --- | --- |
| 客户端 | 目标平台的 Codex Desktop；普通浏览器页面不能作为宿主 |
| 构建工具 | Bun `1.3.13`，项目依赖使用锁文件安装 |
| 加载工具 | 目标操作系统的原生 Node.js `22+` |
| Loader | 已审阅的 Codex Script Loader `0.6.0` 源码，固定提交 `b6ec28c69af12e9667f57d19823fb46d225756e4` |
| 测试目录 | 一个空的独立 Loader 数据目录；诊断输出放在另一独立目录 |

Loader 来源和复用方式见[参考来源](参考来源.md)。需要事先按固定版本的上游说明完成 Loader 自身的环境准备；项目构建不会自动安装 Loader。macOS 入口会核对 Loader 提交和干净工作树。

Windows 加载命令在原生 PowerShell 中执行，macOS 命令在本机终端执行。WSL 单测通过不代表原生 Windows 加载通过。

准备加载前先结束正在执行的任务，并保存需要保留的工作。正常退出客户端后再经 Loader 启动；不要同时从普通快捷方式启动另一份客户端。

## 构建开发版

在项目根目录执行：

```sh
bun install --frozen-lockfile
bun run check
bun run test
bun run build
```

| 产物 | 用途 |
| --- | --- |
| `dist/plugin/` | 实际显示余量的开发版插件，包含入口、manifest、说明和许可 |
| `dist/probe/` | 手动诊断 Renderer 能力与挂载位置的 P0 探针 |
| `dist/app-server-probe.mjs` | 独立 App Server 诊断工具，不是插件数据源 |

日常开发试用只加载 `dist/plugin`。不要同时启用插件和 P0 探针来判断界面结果。

## 加载开发版

以下路径变量均为占位，需要替换成当前机器的真实位置。`TestData` 应是空的独立测试目录，不能指向正在使用的 Loader 注册表。准备脚本仅配置注册表，不启动客户端；发现已有插件时会拒绝操作。

### Windows x64

在原生 PowerShell 中进入项目根目录，设置路径：

```powershell
$NodeExe = 'C:/path/to/node.exe'
$LoaderRoot = 'C:/path/to/codex-script-loader'
$TestData = 'C:/path/to/empty-cui-test-data'

& $NodeExe tools/probes/prepare-loader.mjs $LoaderRoot dist/plugin $TestData
& $NodeExe "$LoaderRoot/src/cli.mjs" scripts --data-dir $TestData
```

确认注册表中仅本项目插件启用，上游默认示例禁用。正常退出所有 Codex 窗口后，在保持打开的终端执行：

```powershell
& $NodeExe "$LoaderRoot/src/cli.mjs" run --live --data-dir $TestData
```

该流程复用固定上游 Loader。Windows 已有加载与热重载证据，但真实宿主完整安装、卸载、升级仍待验收。历史上的受保护安装目录和退出超时排障见[Windows 接入记录](compatibility/继续实机验证.md)，其中的重启脚本不是本指南的默认步骤。

### macOS Apple Silicon：常驻 Loader

在项目根目录设置路径，使用原生 Node.js 22+：

```sh
NodeExe='/path/to/node'
LoaderRoot='/path/to/codex-script-loader'
TestData='/path/to/empty-cui-test-data'
OutputDir='/path/to/cui-diagnostics'

"$NodeExe" tools/probes/prepare-loader.mjs "$LoaderRoot" dist/plugin "$TestData"
"$NodeExe" tools/probes/load-macos.mjs --check "$LoaderRoot" "$TestData" "$OutputDir"
```

检查通过后，正常退出客户端，再启动：

```sh
"$NodeExe" tools/probes/load-macos.mjs --start "$LoaderRoot" "$TestData" "$OutputDir"
```

如果希望先启动等待入口，再手动退出客户端，可以用 `--wait` 替代 `--start`，最多等待 30 分钟。保持终端会话存活；长时间运行应使用持久 TTY 或经过验证的进程管理器。

入口支持发现 Codex.app 与符合 bundle ID 的 ChatGPT.app，不修改安装包。当前使用常驻连接、页面事件恢复和低频健康检查，历史一次性入口已移除；保留失败终态的修复已合入，真实异常路径仍待实机回归。

客户端已经以调试模式运行且已核对端口时，可使用常驻入口连接：

```sh
Port='已核对的本地CDP端口数字'
"$NodeExe" tools/probes/load-macos.mjs --watch "$LoaderRoot" "$TestData" "$OutputDir" "$Port"
```

工具会核验端口归属及唯一页面目标；不要猜端口或绕过校验。没有调试端口时，正常退出后使用 `--start`。行为及开销证据见[常驻方案](compatibility/resident-injection.md)。

### 确认加载结果

1. 打开已有聊天页面，确认下方出现余量文字，侧栏出现对应圆环。
2. 悬停或点击侧栏圆环，检查详情中的连接状态、周期、更新时间与重置时间。
3. 正常联网时等待超过 30 秒，观察更新时间是否推进；余量数值未变化本身不代表没有刷新。
4. 检查输入、键盘焦点与原生菜单是否正常。缺少安全空间或锚点有歧义时，插件会拒绝挂载。

加载器记录 `running` 只描述流程阶段，仍需确认实际界面、运行进程和后续取数，不能仅看状态文件判定成功。

## 查看余量与详情

- **输入框下方**：仅已有聊天显示；Work 新建窗口和 Codex 新聊天页不创建文字栏或占位。静态文字栏与输入框装饰部分重叠，右对齐；悬停、点击不会打开详情，也不会进入 Tab 顺序。
- **侧栏**：5H 表示 5 小时窗口，WEEK 表示每周窗口。悬停预览详情，点击固定，再次点击同一入口关闭。
- **详情卡片**：展示当前可用窗口、余量、绝对重置时间、更新时间和连接状态。两个圆环共享一张卡片，点击另一圆环切换入口。
- **关闭详情**：点击外部、关闭按钮或按 Esc。Esc 与关闭按钮路径会尝试返回触发圆环焦点。

侧栏使用按钮语义，支持键盘聚焦和原生按钮激活；完整 Tab、Enter、Space 与不同页面的组合仍待平台验收。真实余量为零时，文字和详情显示“已经用尽”，圆环仍保留 0% 数字。很小的正数经四舍五入也可能显示 0%，告警仍根据真实值判断。

仅返回每周额度时，文字栏、侧栏和详情都会移除 5H，保留 WEEK。显示与套餐名称无关，不会用其他模型池补齐窗口。

## 理解数据状态

| 显示或行为 | 含义与处理 |
| --- | --- |
| 连接中 | 尚在建立读取，等待首次成功结果 |
| 已连接 | 已取得支持的额度快照；普通刷新过程中继续显示最近数据 |
| 连接中断 | 读取失败；同账号最近数据可以暂时保留，留意更新时间 |
| 数据已过期 | 最近成功数据已超过 90 秒，不应当作最新额度 |
| 需要登录 | 读取结果提示未授权，请先在客户端检查登录状态 |
| 未取得支持的额度窗口 | 没有可用的受支持窗口，插件不会伪造数值 |
| 已连接 · 数据异常 | 数据质量被标记异常，建议核对原生 Usage 并记录环境 |

正常查询间隔为 30 秒，失败时退避，收到 429 时遵守 Retry-After，因此并非所有情况下都恰好 30 秒更新。没有手动刷新按钮。时间按系统时区显示并附 UTC 偏移，月份使用英文缩写。

原生账号菜单活动会触发保守清空和暂停读取，观察到菜单关闭或回到窗口后重新确认上下文，菜单仍打开时不恢复；这是开发中的隔离策略，真实账号切换仍待验证，不代表已有稳定的宿主账号通知接口。

## 停用、移除与更新

### 常驻 Loader 模式

通过 Loader 禁用或卸载插件会调用停止生命周期，取消请求与定时器，移除文字栏、圆环、详情和相关资源。已有实机停用清理证据，但完整安装/卸载/升级流程尚未验收。

更新前先禁用插件，重新构建，再通过固定 Loader 的包管理流程更新并启用；热重载由 Loader 先停止旧实例再启动新实例。完整升级流程待测，不能仅因构建成功就判定运行中的插件已经更新。不要只删除源码或注册表文件来代替停用。

## 常见问题与排查

| 现象 | 建议检查 |
| --- | --- |
| 构建成功但看不到 UI | 是否加载了 `dist/plugin`，插件是否启用，是否通过 Loader 启动了客户端，当前页面是否有可见聊天输入框 |
| 只有一处显示或页面切换后消失 | 可能缺少安全空间或唯一锚点；记录页面类型、主题和尺寸，不强行插入 DOM |
| 客户端更新后停止显示 | 内部 HTTP 或 DOM 可能漂移；记录 build 和诊断码，重新核对兼容证据 |
| 数据长时间不更新 | 查看详情的状态和更新时间，检查客户端联网与登录；429 或网络错误会延长重试间隔 |
| 与原生 Usage 有少量差异 | 先核对同账号、同窗口、同重置时间并接近同时采样；缓存或采样时间不同不能直接认定冲突 |
| 准备脚本拒绝已有目录 | 改用空的独立测试目录，不删除或覆盖正在使用的注册表 |
| macOS 提示 `client-running` | 正常退出客户端后再用 `--start`，或改用等待退出入口 |
| macOS 状态为 `failed` | 保留有限诊断码并核对进程与本地端口；不要把清理完成理解为加载成功 |
| macOS 重载后消失 | 核对常驻加载器进程和连接状态；缺少安全空间时记录页面与诊断码 |

更深入的数据与锚点诊断见[探针说明](../tools/probes/README.md)。独立 App Server 探针只能辅助对照，不能证明 Desktop 同一账号，也不会让插件恢复读取。
