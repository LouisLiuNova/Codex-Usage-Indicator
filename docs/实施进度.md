# 实施边界与验收进度

本项目按用户指定的《技术验证与实施方案》（2026-11-05）实施。原方案中的“当前不提交”属于只读调研轮次；本轮用户已明确授权开发、测试和分步提交。无 Issue 编号，不虚构关闭关联；本轮不推送、不创建 PR、不合并。

## 检查点

1. P0 基础：固定 TypeScript/Bun 工具链，记录来源、平台门槛和测试命令。
2. P0 数据探针：严格的窗口校验、主池选择、白名单脱敏、有限 stdio RPC 和进程清理；使用模拟服务验证。
3. P0 Renderer 探针：限定当前 app 资源的内部 HTTP 能力识别、安全锚点诊断、可撤销的挂载标记、Loader 生命周期与构建检查。
4. P0 证据：运行本环境允许的探针，记录成功与失败；目标平台真实账号和两个 UI 挂载通过前不进入该平台 P1/P2 整合。

## 验收门槛

Windows x64、Windows ARM64、macOS Apple Silicon 分别记录证据，不互相继承。Linux/WSL 单测、模拟 DOM 和模拟 RPC 不是原生客户端证据。真实验证需要账号归属内存确认、原生 Usage 对照、两个位置安全挂载、输入/发送/键盘不受影响、卸载无残留。

Pro 或其他套餐仅 Weekly 是正常支持。仅按照真实 300/10080 分钟窗口识别，禁止根据套餐推断，不读取额外模型池补齐，不保留上一次响应消失的窗口。

## 范围限制

P0 仅交付手动启用的诊断探针，不提供正式圆环插件，不启动常驻 App Server，不读取/复制凭据，不修改应用安装包，不自动安装 Loader 或重启当前客户端。探针仅调用读 RPC；App Server 自身可能写本地状态。未通过平台门槛时不生成可发布 v0.1.0 ZIP 或宣称兼容。

## 独立数据核心（2026-11-06）

在等待原生客户端进入 Loader 会话期间，`codex/usage-data-core` 分支实现不依赖 DOM 的 UsageStore 与 RefreshScheduler，并以假时钟独立验证；尚未接入 Renderer Provider、宿主焦点/visibility/身份事件或生产 UI。此工作不改变 P0 平台门槛，不将独立核心完成视为 P1 平台整合通过。

Store 保证整份快照替换、只读窗口、账号 revision 作废、同账号失败保留及 90 秒 stale；Scheduler 统一刷新入口，合并并发及短事件、30 秒轮询、挂起超时、Abort/迟到响应隔离、独立新鲜度计时和有上限错误退避。429 的 Retry-After 下限保留到重新启停和上下文切换，前台事件不能绕过。调用层仍须提供已经确认的身份变更通知；无法确认归属时先 changeContext 清空，不能仅根据额度响应推断账号。

当前完整矩阵应运行 `bun run test`，包含原有探针测试及新增 10 项数据状态/调度测试。真实网络限流、系统休眠、身份切换与 UI 行为仍须平台实测。

## 原生 Renderer 续测（2026-11-06）

固定 Loader 已成功启动，真实 CDP 与探针 running 状态已核对。初始执行发生在 UI 挂载前；就绪后重载确认两个锚点各唯一但均不满足现有空间规则，HTTP 候选仍为 0。当前 build 使用 Rspack ESM 缓存与大量 getter 导出，超过探针现有扫描能力；下一步是版本适配评估，不能据此断言上游服务不可用。当前适配器 P0 为 No-go，平台整合仍未通过。详细证据见 Windows 报告。完成诊断后已禁用探针。

后续已修复 Rspack 发现并取得 Renderer 真实双窗口。用户批准了外围预留空间和 rail 内宽自适应的实测布局；两个 v2 挂载适配器已实现，原生双挂载/输入/撤销/清理验证成功。仍须完成平台最终 Go 报告、真实发送与重建等验收；不能将原生 Usage 的旧缓存和新 HTTP 响应的 1% 差异直接标记数据冲突。历史 No-go 仅描述当时的适配器，当前进展以 Windows 报告的最新续测为准。

## 开发版 UI 组件（2026-11-06）

`codex/usage-plugin-integration` 分支开始开发版集成：已实现 RingView、SharedPopover、百分比/告警/绝对时间格式和命名空间 CSS。详情定位使用固定 @floating-ui/dom 1.7.4，开启时注册 autoUpdate、关闭时释放，并避让 Composer 与原生菜单。单窗口切换完全删除 5H 按钮、SVG、标签、详情及对应监听；既有 Weekly-only 属于正常状态。

真实 Windows 短暂预览已使用同一次 Renderer HTTP 数据显示两个位置共4个圆环按钮和共享详情卡片，卡片位于 Composer 上方且没有重叠，输入区宽高不变；裁剪截图已查看并保存在忽略目录，预览 finally 和20秒兜底清理。此预览只读一次额度，不代表自动刷新运行时已经接入；仍须实现正式 Loader start/stop、Provider 与 Scheduler 接线、宿主身份切换事件及重建观察。

键盘边界：DOM 单测中的 Escape 关闭和焦点恢复通过，包括模拟宿主 document 捕获处理器的情况；真实 CDP 发出的 Escape 尚未达到同样结果，短暂诊断在 window 未观察到该 keydown，不能将单测通过替代真实键盘验收。已移除诊断监听，后续须定位当前客户端输入通道/宿主快捷键并重新验收。未宣称 P2 完成或可发布。
